推测解码与MTP#

在自回归 LLM 中，模型要先生成第一个 token，才能确定预测第二个 token 时应当读入什么。如果先给它一段候选文本，情况就变了：各位置的候选前缀都已知，大模型一次前向就能给出每个位置的条件分布。推测解码（Speculative Decoding）利用这个性质，把逐词生成中的一部分工作转化为并行验证。推测级联进一步改变验证时采用的目标分布。多 token 预测（Multi-Token Prediction，MTP）则从训练入手，让同一段前文为多个未来位置提供预测，其中的辅助预测可以用来起草。 〔1〕 〔2〕

3. SpecDec 与 DistillSpec#

SpecDec 原论文图 4。同一处候选在严格匹配下会产生分歧，放宽排名和对数概率差要求后，可以继续验证后续位置。 〔8〕

  • SpecDec。 在序列到序列任务中，使用独立的 Spec-Drafter，根据源输入和目标前缀并行预测一个块。作者把较多容量分配给只需编码一次的源端，减少反复运行的解码端开销，用序列级蒸馏训练草稿器。
  • Spec-Verification。 记目标分布为 pjp_jpj​。候选须进入前 β\betaβ 名，同时与最优词的对数概率差 log⁡max⁡vpj(v)−log⁡pj(dj)\log\max_v p_j(v)-\log p_j(d_j)logmaxv​pj​(v)−logpj​(dj​) 落入容许范围。这两个条件分别控制排名和分数差距。即使候选排第二，它也可能与第一名相差很远。
  • 与严格采样的区别。 此处允许提交一个满足阈值的次优词，衡量的是翻译或摘要等任务的质量。前节的概率比和残差修正则给出对指定分布的严格保证。

DistillSpec 原论文图 3 是机制消融图。左图比较不同蒸馏策略的接受率，中图比较蒸馏前后的块效率，右图对照理论块效率和实测值。 〔9〕

  • DistillSpec。 保留独立的小型自回归草稿器，改变其训练目标。让学生在自己的轨迹上生成前缀，再让教师给这些位置提供完整的下一词分布。用 dqd_qdq​ 表示草稿器实际访问的前缀分布，目标可概括为
min⁡θ Eh∼dqθ[D(p(⋅∣h),qθ(⋅∣h))].\min_\theta\ \mathbb E_{h\sim d_{q_\theta}} \big[D\big(p(\cdot\mid h),q_\theta(\cdot\mid h)\big)\big].θmin​ Eh∼dqθ​​​[D(p(⋅∣h),qθ​(⋅∣h))].

散度 DDD 按任务和解码方式选择。训练时接触过自己容易走偏的前缀，学生才有机会在这些位置学到教师的分布。

  • 与 SpecDec 的区别。 SpecDec 设计并行块预测器，并研究放宽验证。DistillSpec 的主要改动在起草前的蒸馏；它可以继续使用严格验证，在保持目标分布的条件下提高平均接受长度。

4. Draft & Verify 与 Predictive Pipelined Decoding#

Draft & Verify 原论文图 1。起草使用跳层的网络，验证使用完整网络。 〔10〕

  • 跳层。 同一组模型参数按两种方式执行。起草时跳过选定的注意力或前馈子层，以较低成本生成多个词；验证时走完整的目标模型。跳过哪些子层会同时影响草稿速度和准确性，论文在样本上搜索跳层策略。
  • 自适应停止。 当下一个草稿词的置信度过低时，可以提前结束起草，把已有候选交给完整网络。这里的置信度控制草稿长度，最终能否提交仍由验证结果决定。

Predictive Pipelined Decoding 原论文图 1。右侧沿时间轴排列多个前向过程，错误候选对应的后续分支会终止。 〔11〕

  • 提前启动下一步。 当前 token 的完整前向仍在进行时，用中间层表示预测它可能取的值。分配额外计算资源，以候选词作为输入，提前启动下一个位置的前向。等深层结果可用后，保留与完整模型一致的分支。
  • 与跳层的区别。 跳层先廉价地写一块草稿，再让完整网络读一遍；流水线让相邻 token 的计算在时间上重叠。早期预测命中才有可复用的工作，分支越多，占用的并行计算资源越多。

5. Jacobi 并行解码与 Lookahead Decoding#

Santilli 等原论文图 1。左侧为自回归翻译，右侧用初始猜测填满多个目标位置，在一次迭代里同时更新。 〔12〕

  • Jacobi 更新。 给定源句 xxx 和固定长度的目标位置，贪婪解码的结果满足 yi=arg⁡max⁡vp(v∣x,y<i)y_i=\arg\max_v p(v\mid x,y_{<i})yi​=argmaxv​p(v∣x,y<i​)。先用占位 token 等方式初始化猜测，在第 s+1s+1s+1 轮同时计算
yi(s+1)=arg⁡max⁡vp(v∣x,y<i(s)).y_i^{(s+1)}=\arg\max_v p(v\mid x,y_{<i}^{(s)}).yi(s+1)​=argvmax​p(v∣x,y<i(s)​).

同一轮的各位置都读上一轮的猜测。每轮至少可使正确前缀再向前延伸一个位置，猜对的远端位置还可能提前稳定。论文还研究按块处理和随后切回自回归的方式。总收益取决于迭代次数及每轮成本。

Lookahead Decoding 原论文图 1。左侧分支形成候选 n-gram，验证分支读取与当前前缀相接的候选。 〔13〕

  • 收集候选。 保留多个位置在连续 Jacobi 迭代中的预测轨迹，抽取沿轨迹形成的 n-gram，写入候选池。一个局部片段即使当时位于错误前缀后面，也可能在稍后的正确前缀上派上用场。
  • 取出并验证。 根据当前已确认的末词从池中选出若干续段，使用目标模型并行验证。前瞻分支生成新片段，验证分支提交可接受前缀，两者可以合到一次带掩码的前向里。
  • 与 Jacobi 的区别。 Jacobi 通过迭代求整段或一块的固定点；Lookahead 把中间轨迹当成草稿来源，依靠显式验证推进已确认前缀。它的草稿池可以在解码过程中建立。

6. SpecInfer 与 Medusa#

SpecInfer 原论文图 2。上半部把多个候选组织成树，下半部在目标模型中验证各条可行路径。 〔14〕

  • 从链到树。 若多个草稿共享首词，将共同前缀存成同一节点，随后才分叉。对树中节点 uuu，目标模型应给出 p(⋅∣h,path⁡(u))p(\cdot\mid h,\operatorname{path}(u))p(⋅∣h,path(u))。比较候选节点自身时，要读取其父节点对应的预测。
  • 树注意力。 每个候选位置可以关注公共前缀、自己的祖先及自身，屏蔽兄弟节点。并行处理一棵树就能得到多条路径上的条件分布。提交选中的路径后，只保留这条路径所需的缓存。树增宽可以覆盖更多候选，也会消耗更多验证位置。

Medusa 原论文图 1。左侧为共享主干，中间的附加头预测不同偏移量，右侧各头的高分候选按偏移量排列，下方展示从中选择并验证的续段。 〔15〕

  • 多头起草。 设 hth_tht​ 为主干顶层状态。原始头预测 xt+1x_{t+1}xt+1​，第 kkk 个附加头从同一 hth_tht​ 预测 xt+k+1x_{t+k+1}xt+k+1​。每个头可以保留多个高分词，按预设树结构选择部分组合，再用树注意力验证。
  • 训练和接受。 Medusa-1 冻结主干、训练附加头；Medusa-2 联合微调。采用贪婪一致性验证时，结果对齐所用目标模型的贪婪输出。论文也讨论 typical acceptance，即根据目标概率和熵放宽接受条件，此时应同时测量生成质量。
  • 与 SpecInfer 的区别。 SpecInfer 把外部草稿模型产生的多个候选合并成树；Medusa 在目标模型主干上训练未来位置的预测头。两者共享树形验证思路，草稿的生成成本和新增参数不同。

普通级联先运行小模型，再决定是否转交大模型。路由可以发生在整条请求上，也可以发生在每个 token 上。以 token 级联为例，在前缀 hhh 处，记 δ(h)∈{0,1}\delta(h)\in\{0,1\}δ(h)∈{0,1}，取 1 表示转交。最终使用的分布为

当 ℓq−ℓp>α TV(p,q)\ell_q-\ell_p>\alpha\,\mathrm{TV}(p,q)ℓq​−ℓp​>αTV(p,q) 时转交。真实标签在推理时未知，论文在 0–1 损失下用 1−cq1-c_q1−cq​ 与 1−cp1-c_p1−cp​ 近似两端风险，得到表中最后一行。模型的置信度校准会影响这项近似。

  • 两个模型都可能对各自的首选词很有把握，但草稿实际采到的是另一个词。令 rh(v)∈{0,1}r_h(v)\in\{0,1\}rh​(v)∈{0,1} 判断词 vvv 是否需要转交。例如，当 p(v∣h)p(v\mid h)p(v∣h) 相对 cpc_pcp​ 过低时取 1。此时路由随 vvv 变化，论文式（11）把被转交的总质量重新分配给大模型：
η=∑v∈Vq(v∣h)rh(v),πh(v)=q(v∣h)(1−rh(v))+η p(v∣h).\eta=\sum_{v\in V}q(v\mid h)r_h(v),\qquad \pi_h(v)=q(v\mid h)(1-r_h(v))+\eta\,p(v\mid h).η=v∈V∑​q(v∣h)rh​(v),πh​(v)=q(v∣h)(1−rh​(v))+ηp(v∣h).

求和可得 ∑vπh(v)=(1−η)+η=1\sum_v\pi_h(v)=(1-\eta)+\eta=1∑v​πh​(v)=(1−η)+η=1。有了这个分布，再用前节的通用采样器验证。“这批候选中哪些词值得保留”和“最后按照哪个分布采样”是两个连续的计算步骤。

四、MTP#

9. Blockwise Parallel Decoding#

Stern 等原论文图 1。自上而下依次是提出整块、验证候选前缀和接受最长匹配前缀。 〔17〕

  • 多头预测。 给定 h=x≤th=x_{\le t}h=x≤t​，主干得到隐藏向量 zt∈Rdz_t\in\mathbb R^dzt​∈Rd。多个输出分支分别预测偏移 1,…,k1,\ldots,k1,…,k。论文的 Transformer 实现在解码器顶层加入有残差连接的多输出前馈层，再对各分支使用原有的词表投影。ztz_tzt​ 是隐藏向量，经过词表投影后才得到 ∣V∣|V|∣V∣ 维 logits。
  • 并行。 令 x^t+j=arg⁡max⁡vqj(v∣h)\hat x_{t+j}=\arg\max_v q_j(v\mid h)x^t+j​=argmaxv​qj​(v∣h)。第二个头和第一个头读取相同前缀，因此第二个头输出的是对未来第二个词的直接预测。验证时，主头会读取已经提出的第一个词，重新判断第二个位置：
ℓ=max⁡{s≤k: ∀j≤s, x^t+j=arg⁡max⁡vp(v∣h,x^t+1:t+j−1)}.\ell=\max\{s\le k:\ \forall j\le s,\ \hat x_{t+j}=\arg\max_v p(v\mid h,\hat x_{t+1:t+j-1})\}.ℓ=max{s≤k: ∀j≤s, x^t+j​=argvmax​p(v∣h,x^t+1:t+j−1​)}.
  • 严格贪婪版本中，第一个候选取自主模型的一步预测。后续只保留连续匹配部分，即使较远的某个头单独猜对了，也不能跨过中间的错误直接提交。

同一论文图 2。右侧的 reused 表示复用与已接受前缀对应的下一块候选。

  • 重叠两轮。 在候选前缀的各位置上运行多头模型，第一头为本轮验证提供分数，其余头为可能的下一轮提前提出候选。确定接受长度后，复用正确前缀所在位置的结果。若每次都前进 kkk 步，长为 mmm 的生成约需 m/km/km/k 轮，实际时间还取决于多头和验证的成本。
  • 与独立小模型的区别。 ABC 草稿里的 CCC 以已起草的 ABABAB 为条件；Blockwise 的远端头在第一次提案时还看不到近端头选中的词。两者都可以做最长前缀验证，草稿内部的条件依赖不同。

10. Meta MTP#

Gloeckle 等原论文图 1。上半部的多个预测头读取同一份主干表示，下半部报告作者在代码任务中的结果。 〔18〕

  • 网络结构。 共享因果主干产生 z≤t=F(x≤t)z_{\le t}=F(x_{\le t})z≤t​=F(x≤t​)。第 jjj 个头各有自己的 Transformer 层 fjf_jfj​，最后共享词表投影 WUW_UWU​：
qj(⋅∣x≤t)=softmax⁡ ⁣(WU[fj(z≤t)]t),标签为 xt+j.q_j(\cdot\mid x_{\le t}) =\operatorname{softmax}\!\left(W_U[f_j(z_{\le t})]_t\right), \qquad \text{标签为 }x_{t+j}.qj​(⋅∣x≤t​)=softmax(WU​[fj​(z≤t​)]t​),标签为 xt+j​.
  • 训练。 数据中所有未来标签都已知，令 Ij\mathcal I_jIj​ 为第 jjj 个标签仍在窗口内的位置集合。忽略统一的损失缩放，多头交叉熵可写为
Lmulti=−∑j=1n∑t∈Ijlog⁡qj(xt+j∣x≤t).\mathcal L_{\rm multi}=-\sum_{j=1}^n\sum_{t\in\mathcal I_j} \log q_j(x_{t+j}\mid x_{\le t}).Lmulti​=−j=1∑n​t∈Ij​∑​logqj​(xt+j​∣x≤t​).

ztz_tzt​ 同时收到多个未来位置的梯度。当一个前缀中的关键信息会影响后续若干词时，预测这些词都能为主干提供监督。训练时可以逐头计算词表投影、损失及反向传播，累积主干梯度，减少同时保留多份大词表张量造成的显存峰值。

  • 推理。 单独使用第一头即可普通生成；也可以使用远端头并行起草，再用第一头验证。四个头输出四份分布，不保证四个候选连在一起就构成第一头会逐步生成的序列。
  • 与 Blockwise 的区别。 Blockwise 的重点是用额外的前馈预测分支减少解码轮数；Meta 将多位置预测用于预训练，各偏移量采用独立的 Transformer 头。这里的 Transformer 层已经包含注意力和前馈子层。与 Medusa 相比，Meta 重点考察多标签监督能给共享主干带来多少训练收益。

五、加速比#

设一轮提交的 token 数为 NNN。在严格单链采样中，拒绝时提交一个修正词，全通过时额外提交一个词。暂忽略 EOS 和长度上限，一轮的提交数就是“连续接受的草稿数加一”。记 AjA_jAj​ 为第 jjj 个草稿通过，则

E[N]=1+∑j=1γPr⁡(A1∩⋯∩Aj).\mathbb E[N]=1+\sum_{j=1}^\gamma \Pr(A_1\cap\cdots\cap A_j).E[N]=1+j=1∑γ​Pr(A1​∩⋯∩Aj​).
  • 连续前缀。 第三个词即使常常猜对，只要第一个词频繁被拒绝，第三个词就很少有机会提交。若每一位置在此前均通过的条件下，接受概率都近似为 aaa，上式化为 1+a+⋯+aγ1+a+\cdots+a^\gamma1+a+⋯+aγ，当 a=1a=1a=1 时为 γ+1\gamma+1γ+1。
  • 一轮耗时。 设目标模型普通单步耗时为 tpt_ptp​，起草、验证和调度的单轮总耗时分别为 Td,Tv,ToT_d,T_v,T_oTd​,Tv​,To​，在相同硬件、批量与解码设置下，可估计稳态加速比
S≈E[N] tpE[Td+Tv+To].S\approx\frac{\mathbb E[N]\,t_p}{\mathbb E[T_d+T_v+T_o]}.S≈E[Td​+Tv​+To​]E[N]tp​​.

当小批量解码主要受权重读取带宽限制时，一次让目标模型验证几个位置可以复用已读入的权重。增大草稿长度或树宽也会增加计算、激活与 KV 开销。若 GPU 已被大批量请求充分利用，TvT_vTv​ 与普通单步耗时的差距可能变大。

  • 对齐评测口径。 对严格贪婪解码，应比较同一目标模型的输出序列；严格随机采样对应的是输出分布；对宽松验证和推测级联，要在同一任务质量附近比较延迟。报告草稿长度、平均提交长度、每秒输出 token 数，并区分首 token 延迟与后续生成延迟，才能判断收益来自哪里。
